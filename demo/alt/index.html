What is STRATA?

The problem

Coding agents now write whole ML pipelines over relational data with timestamps. The code runs, the tests pass, the score looks good. A model built to predict what happens after a date t can still use facts that only appeared after t. Offline it looks excellent; in production it fails, and nothing in the code or the metric shows why. This is a point-in-time (PIT) leak.

The future can get in at five places, and a check of one place passes a pipeline that leaks in another:

task rows for entities that do not exist yet at t; labels used before they are complete
features rows created after t; dates filled in later; values overwritten at the end of the data
model training rows whose outcome was not known at t
in-context few-shot examples for an LLM taken from after t
agent a model that recognises an entity instead of learning about it from the data

One rule for all five

output on D  =  output on D as of t

STRATA never reads the code. It runs each layer on the full database and on the database as it was at t (rows that did not exist yet removed, values filled in later blanked) and compares the outputs. A difference is a LEAK with a witness: the time, the entity, the column and the channel that carried the future. No difference at the tested times is CLEAN. If the output depends on a column whose availability nobody knows, the verdict is UNCHECKABLE, never a false CLEAN.

Mutants: one time comparison changed at a time in a reference pipeline, each labelled by hand as a leak or harmless. Weaker detectors: cutting rows at t finds 11 of 25 leaking control programs, adding late dates and a canary finds 16, and both miss every overwritten value.

Use it from a coding agent

Install the package, drop SKILL.md into the agent's skills, and it will run the check before reporting a score. The skill says which check to call for which layer, how to read a witness, and that only a rerun may declare a leak fixed.
